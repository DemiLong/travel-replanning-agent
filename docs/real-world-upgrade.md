# Dayshift v3 可靠性收敛说明

## 产品边界

Dayshift 面向中国境内、已有正式行程的单日动态调整。创建页负责维护事实，首页负责接住一次变化，复杂活动编辑进入救援页，结果页负责展示与接受方案。

系统不处理多日、海外、账号同步、预订、社交和长期兴趣推荐。超出边界的输入必须以 `OUT_OF_SCOPE` 结束，不能默认为优化。

## 主链路

```text
首次输入
  → DeepSeek Parser（8 秒）
  → 输入门控
  → 确定性合并事实
  → 高德 Grounding（单请求 8 秒）
  → DeepSeek Planner（单轮 10 秒，最多两轮）
  → Validator
  → READY / NO_SAFE_PLAN

补充回答
  → 按 blocker key 定向更新一个字段
  → Grounding → Planner → Validator
```

整个 `/api/assist` 请求有 30 秒截止时间。解析、查询、规划只属于单次请求；浏览器只保存业务终态。

## 防循环与事实隔离

`MissingFact` 包含稳定 `key`、问题、答案类型和可选候选。Session 的 `resolutionState` 保存当前 blocker、重复次数、总轮数、已回答字段和问题历史。

- 同一 blocker 第一次可自由补充。
- 第二次使用时间、地点候选、活动选择或浏览器定位等结构化控件。
- 第三次重复或总轮数超过三次时安全结束，原行程不变。
- 续接请求必须携带当前 blocker 对应的字段答案；过期或越权答案会被拒绝。

## 数据与迁移

浏览器会话键为 `travel-session-real-v3`。v2 加载时先复制到备份键，再迁移日期、活动、固定状态和 revision。行程被统一为同一天；已移除的旧字段会被 Zod schema 丢弃。迁移失败时原备份保留，并创建干净 v3 Session。

`stateCapturedAt` 记录当前状态确认时间。重新打开旧会话时刷新系统时钟；用户刚明确确认的当前时间在有效窗口内优先。

## 真实世界与校验

世界服务只查询当前决策需要的路段：当前位置到下一活动、相邻活动、固定预约必要路段，以及替代地点进入方案所需的路段。高德原始路线返回值可留作证据，但不会影响产品取舍。

Planner 默认给一个推荐方案，最多附一个取舍真正不同的备选。固定预约、已完成活动、地点身份和用户确认时长由代码校验。接受方案前 `/api/validate` 会重新 Grounding、检查数据新鲜度，并由浏览器仓储检查 revision。

## 故障语义

业务响应仅有：

```text
READY | NEEDS_INPUT | OUT_OF_SCOPE | UPSTREAM_UNAVAILABLE | NO_SAFE_PLAN
```

上游失败包含失败阶段、是否可重试和用户可行动说明。任何失败都不能修改正式行程，也不能重跑已确认的全文解析。

## 自动验证

默认离线测试覆盖：迁移、输入门控、字段隔离、防循环、候选上限、Planner 两轮上限和固定安排保护。真实 DeepSeek 与高德调用保留为手动脚本，不进入默认 CI。
